# Qadam — AI-платформа для малого и среднего бизнеса

Qadam — веб-платформа для управления бизнес-процессами и общения с клиентами. Проект объединяет CRM-инструменты и ИИ-продавца, который отвечает клиентам на основе информации о компании, её товарах, ценах и условиях доставки.

> **Статус проекта:** прототип для демонстрации и дальнейшей разработки. Перед использованием в реальном бизнесе необходимо проверить сценарии, безопасность, настройки базы данных и работу интеграций.

## Возможности

- **CRM:** обзор, контакты, задачи и рабочие записи.
- **B2B-каталог:** просмотр товаров, фильтрация и связанные сценарии заказов/сообщений.
- **ИИ-продавец:** потоковый чат на русском и казахском языках; ответы формируются на основе профиля компании.
- **История диалогов:** сохранение сообщений в Supabase.
- **Документы:** инструменты для подготовки документов и экспорта в PDF/DOCX.
- **Интерфейс:** светлая и тёмная темы.

### Ограничения

- Реальные интеграции с WhatsApp, Instagram и Telegram не включены. Для них потребуются отдельные API, настройка вебхуков и соответствующие разрешения.
- ИИ-функции требуют действующего доступа к Lovable AI Gateway и серверного ключа.
- Документы, генерируемые приложением, не заменяют юридическую проверку.
- Фактическая доступность функций зависит от корректной настройки Supabase, миграций и переменных окружения.

## Локальный запуск

1. Клонируйте репозиторий и перейдите в папку проекта:

   ```bash
   git clone https://github.com/smoqalik23/QadamProject
   cd <ПАПКА-ПРОЕКТА>
   ```

2. Установите зависимости:

   ```bash
   npm install
   ```

3. Создайте локальный файл окружения на основе примера:

   **macOS / Linux**
   ```bash
   cp .env.example .env
   ```

   **Windows PowerShell**
   ```powershell
   Copy-Item .env.example .env
   ```

4. Заполните `.env` реальными значениями из настроек Supabase и Lovable. Не оставляйте значения-заполнители.

5. Убедитесь, что SQL-миграции применены к нужной базе данных Supabase. Файл миграции проекта находится в `drizzle/migrations/`. Не предполагайте, что наличие SQL-файла автоматически создаёт таблицы в удалённой базе.

6. Запустите приложение:

   ```bash
   npm run dev
   ```

   Откройте URL, который выведет Vite в терминале.

## Переменные окружения

| Переменная | Назначение | Обязательность |
|---|---|---|
| `SUPABASE_URL` | URL проекта Supabase для серверного кода | Обязательна |
| `SUPABASE_PUBLISHABLE_KEY` | Публичный ключ Supabase для серверных запросов от имени пользователя | Обязательна |
| `VITE_SUPABASE_URL` | URL Supabase, доступный клиентской сборке | Рекомендуется задать |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Публичный ключ Supabase для клиентской сборки | Рекомендуется задать |
| `SUPABASE_SERVICE_ROLE_KEY` | Привилегированный серверный ключ для административных операций, обходящих RLS | Нужна функциям, использующим серверный admin-клиент |
| `LOVABLE_API_KEY` | Ключ Lovable AI Gateway для ИИ-продавца | Обязательна для ИИ-чата |
| `LOVABLE_DB_MIGRATION_URL` | Строка подключения к PostgreSQL для Drizzle Kit | Нужна только для запуска инструментов миграции через Drizzle Kit |
| `LOVABLE_CRON_SECRET` | Секрет для авторизации защищённых cron-запросов | Нужен, если используются cron-маршруты |
| `LOVABLE_CRON_SECRET_PREVIOUS` | Предыдущий cron-секрет на время ротации | Необязательна |

`VITE_*` переменные встраиваются в клиентскую сборку. Используйте с ними только публичные значения. **Никогда не добавляйте `SUPABASE_SERVICE_ROLE_KEY`, `LOVABLE_API_KEY`, пароли базы или другие секреты в переменные `VITE_*`.**

`SUPABASE_SERVICE_ROLE_KEY` обходит Row Level Security. Он должен храниться только в серверном окружении и не должен попадать в браузер или публичный GitHub-репозиторий.

## Команды

```bash
npm run dev       # локальная разработка
npm run build     # production-сборка
npm run preview   # локальный просмотр production-сборки, если поддерживается конфигурацией
npm run lint      # проверка ESLint
npm test          # запуск тестов
npm run test:watch # тесты в watch-режиме
```

После изменения переменных `VITE_*` перезапустите dev-сервер и заново соберите приложение для production.

## Деплой

Конфигурация проекта использует TanStack Start и Nitro; в `vite.config.ts` сборка настроена с целью Cloudflare по умолчанию через Lovable-конфигурацию. Поэтому сначала проверьте deployment flow для Cloudflare Workers и совместимость используемых серверных API.
